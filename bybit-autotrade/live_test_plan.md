작성 2026-10-13. **실전·데모 결과를 하나도 보기 전에 작성했다. 이후 내용은 고치지 않는다.** 바꿔야 하면 맨 아래 "변경 기록"에 날짜·이유를 덧붙이고, 바뀐 기준은 그 시점 이후 표본에만 적용한다. 이 파일의 md5 는 처음 실전 체결 전에 `data/plan_md5.txt` 에 남긴다.

## 1. 무엇을 확인하나
- **주 질문 (이번 검증으로 답할 수 있음)**: 사이트(스크리너 눌림목H)가 계산하는 리플레이 결과가 실제 체결에서 얼마나 깎이나 — 체결 여부, 체결가, 수수료, 슬리피지, 펀딩, 손절·익절 체결.
- **보조 질문 (이번 검증으로는 판정 못 함)**: 엣지(기대값 > 0)가 살아 있나. 거래당 표준편차가 약 20%라 30건이면 평균의 95% 범위가 ±7%p — 기대값 +1% 를 0 과 가르려면 약 1,500건이 필요하다. 엣지는 사이트의 전체 사건 기록(h_history)으로 몇 달 따로 본다.

  - 진입: 스크리너 S1 사건 중 사이트 H3 대상(B·Q 거르기 통과) → 사이트 지정가(신호 종가 × 0.95) 24시간 유효.

  - H4: +12%에서 절반 익절, 나머지는 손절을 +0.5%로 올림, 168시간.
  - H5: +5% 닿으면 손절 +0.5%, 168시간.
- 크기: 손절 시 손실 = 전략 예산의 0.25%. 바이비트 최소 주문 5 USDT 때문에 최대 0.5%까지 허용하고, 넘으면 건너뛴다.
- 레버리지: 청산가가 손절가보다 5%p 이상 멀도록 자동 계산, 상한 5배(보통 4배). 격리 마진.
- 한도: 일일 손실 6%면 그날 진입 중단, 누적 손실 20%면 그 전략 정지. 동시 포지션은 전략당 60개까지(사실상 전부 받음).

## 3. 표본과 기간
- 시작: live 장부의 첫 체결 시각. 지금(10/13)은 BTC 저변동이라 live 관문이 닫혀 있을 수 있다. 그 기간은 기다림이고 실패가 아니다.
- **목표: live H3 청산 완료 30건.** 관문이 열려 있으면 하루 체결 약 5건, 72시간 보유라 대략 2~3주.
- 최대 기간: 시작 후 8주. 그때까지 30건이 안 되면 있는 표본으로 정리하고 "표본 부족"으로 표시한다.
- demo 목표: 전략마다 청산 100건 또는 8주 중 먼저 오는 쪽.

## 4. 측정 (미리 정한 계산)
매 거래마다 같은 사건의 사이트 결과(`legs.site_result`)와 짝을 짓는다. 사이트 결과 키는 H3 → H72, H4 → PT12_168, H5 → LK5_168이고, 사이트 숫자는 수수료 0.11%를 뺀 값이다.

1. **실행 차이 d** = 실전 수익률(%, 실제 수수료·펀딩·슬리피지 포함) − 같은 사건 사이트 결과(%).
   - 평균과 95% 범위를 계산한다. 하루 단위로 다시 뽑기 2,000회.
   - 구성도 따로 본다: 진입 체결가 − 지정가(bp), 청산 체결가 − 기준가, 수수료 합, 펀딩 합, 손절 체결가 − 손절가.
2. **체결 일치율**
   - 사이트가 지정가 체결로 본 사건 중 봇도 체결한 비율. 관문으로 건너뛴 사건은 빼고, 봇이 켜져 있던 시간만 센다.
   - 반대로 봇이 체결했는데 사이트는 미체결인 비율.
3. **실전 평균 수익률**과 같은 사건 사이트 평균 비교. 참고로 과거 기대값도 함께 적는다.
   - 바이낸스 확인 H3: +2.12% (수수료 0.11%, 손절 없음)
   - 손절 −15%와 실제 비용을 반영한 추정: +0.5 ~ +1.4%
4. **안전장치 기록**: 손절 없는 포지션이 있었던 시간, 중복 주문, 한도 초과 주문 시도, API 오류 횟수.

## 5. 성공·실패 기준 (live, 청산 30건 시점)
**성공 (모두 충족)**
- S1. 실행 차이 평균 d ≥ −0.5%p, 그리고 95% 범위 하한 ≥ −1.0%p.
- S2. 체결 일치율 ≥ 90% (양방향 모두).
- S3. 같은 사건의 사이트 평균이 플러스면, 실전 평균 ≥ 사이트 평균의 절반. 사이트 평균이 0 이하면 S1로 갈음한다.
  - S3은 30건에서 잡음이 매우 크다(±7%p). 그래서 참고 성격이고, 결정은 S1·S2가 한다.
- S4. 안전장치 오작동 0건.

**실패 (하나라도 해당)**
- F1. 실행 차이 평균 d < −1.0%p.
- F2. 체결 일치율 < 80%.
- F3. 손절 없는 포지션이 5분 넘게 있었거나, 중복 주문이나 한도 초과 주문이 실제로 나감.

S도 F도 아니면 "판정 보류"로 두고, 같은 규칙으로 60건까지 늘린다.

## 6. 중단 규칙 (멈추고 다시 분석)
- 누적 손실 20% (자동 정지): 원인 분석 문서를 쓰기 전에는 재개하지 않는다. 재개는 설정 파일 숫자 변경으로만 한다.
- 일일 손실 6%: 그날 자동 중단, 다음 날 자동으로 다시 열린다.
- F3에 해당하는 일 1건: 즉시 /정지 후 분석.
- 첫 10건의 실행 차이 평균이 −2%p 이하: 조기 경보로 일시 정지하고 원인을 분석한다(판정 아님).
- API 오류로 진입이 막힌 일이 한 주에 3번 이상: 원인 분석.
- 8주 경과: 결과 정리.

## 7. 범위 밖
- 이 검증으로 "엣지가 있다/없다"를 판정하지 않는다(1절).
- 손절·보유 시간·레짐 문턱을 결과를 보고 바꾸지 않는다. 바꾸면 새 검증이다.
