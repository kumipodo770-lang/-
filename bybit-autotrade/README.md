# 바이비트 실전 검증 자동매매 (H3·H4·H5)

목적은 수익이 아니라 **사이트(스크리너 눌림목H) 리플레이 기대값이 실제 체결에서도 유지되는지** 재는 것입니다. 계획은 `live_test_plan.md`에 있습니다.

- 스크리너는 API로 **읽기만** 합니다 (`/api/hplan`). 스크리너 파일은 하나도 고치지 않습니다.
- 모드 3개:
  - `paper`: 실시간 시세 + 가상 체결 (기본값)
  - `demo`: 바이비트 데모 트레이딩
  - `live`: 실계좌. **사용자만 켤 수 있습니다** (아래 5절).
- 출금 기능은 없습니다. 바이비트 키에는 출금 권한을 주지 마세요.

## 2. 비밀값 넣기 (사용자가 직접)
`.env.example`을 복사해 같은 폴더에 `.env`로 저장하고 메모장으로 값을 넣습니다. 봇만 이 파일을 읽고, 화면·로그에는 값이 나오지 않습니다.

| 이름 | 무엇 | 없으면 |
|---|---|---|
| `SCREENER_PASSWORD` | 스크리너 사이트 비밀번호 | 신호를 못 받음 |
| `DASH_PASSWORD` | 휴대폰 웹 화면 비밀번호 (10자 이상, 스크리너와 다르게) | 웹 화면 꺼짐 |
| `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` | 텔레그램 알림·정지 버튼 | 알림 없음 |
| `BYBIT_DEMO_API_KEY` / `_SECRET` | 데모 트레이딩 키 | demo 장부 꺼짐 |
| `BYBIT_LIVE_API_KEY` / `_SECRET` | 실계좌 키 | live 장부 꺼짐 |

**바이비트 키 만들 때**
- 권한은 "읽기 + 거래(Contract · Orders · Positions)"만 줍니다. 출금(Withdraw)·이체는 끕니다.
- 가능하면 IP 제한을 겁니다(이 PC의 공인 IP).
- 데모 키: 바이비트 메인 계정에서 "데모 트레이딩"으로 바꾼 뒤, 프로필 → API에서 만듭니다(테스트넷 키 아님).
- 데모 계정에 가상 USDT가 필요하면 웹 화면에서 데모 트레이딩으로 들어가 신청합니다.

**계정 설정 (사용자가 바이비트 앱에서 직접)**
- 통합계정(UTA)의 마진 모드를 **격리(Isolated Margin)**로 둡니다. 봇은 확인만 하고 바꾸지 않습니다. 격리가 아니면 그 장부는 진입을 멈추고 알림을 보냅니다.
- 포지션 모드는 **원웨이(One-way)**여야 합니다.
- 본계정을 쓸 때 주의할 점:
  - 봇이 들고 있는 코인을 손으로 매매하지 마세요. 한 코인에 포지션이 하나뿐이라 섞입니다.
  - 봇은 자기 것이 아닌 포지션이 있는 코인의 신호는 건너뜁니다.

## 3. 실행
- `run_bot.bat`을 더블클릭합니다. 창이 떠 있는 동안 동작합니다.
- 시작하면 텔레그램으로 "자동매매 시작" 메시지가 옵니다.
- 자동 시작: 윈도 작업 스케줄러에 "로그온 시 run_bot.bat 실행"이 등록되어 있습니다(등록했다면). 해제는 작업 스케줄러에서 `BybitAutoTrade`를 삭제하면 됩니다.
- 봇이 꺼져 있어도 이미 걸린 손절·익절은 거래소 서버에 남아 있습니다. 다시 켜면 다음을 처리합니다.
  - 거래소의 실제 주문·포지션·체결로 기록을 맞춤
  - 꺼진 사이 지난 72시간·168시간 청산을 바로 처리
  - 손절이 없는 포지션이 있으면 다시 걸고 알림

## 4. 휴대폰
- **텔레그램 (알림 + 긴급 정지)**
  1. 텔레그램에서 @BotFather → `/newbot`으로 봇을 만들고, 토큰을 `.env`의 `TELEGRAM_BOT_TOKEN`에 넣습니다.
  2. 봇을 재시작하고, 만든 봇에게 `/start`를 보냅니다.
  3. 웹 화면 맨 아래에 chat id가 뜨면 `TELEGRAM_CHAT_ID`에 넣고 재시작합니다.
  - 명령: `/상태`, `/정지 [장부]`, `/재개 [장부]`, `/청산 [장부]`. 장부를 안 쓰면 전체입니다.
  - 정지·재개·청산은 "확인" 버튼을 60초 안에 한 번 더 눌러야 실행됩니다.
  - 알림: 체결, 청산(손익), 오류, 일일 한도·누적 정지, API 실패로 진입 중단.
- **웹 화면 (상세)**
  - 집 와이파이에서 `http://<이 PC의 내부 IP>:8100`으로 접속하고 `DASH_PASSWORD`로 로그인합니다.
  - 볼 수 있는 것: 장부별 상태, 오늘·누적 손익, 보유·대기 주문, 최근 신호와 진입/건너뜀 이유, 사이트 결과와 짝지은 청산, 오류.
  - 차트: 표의 줄을 누르면 그 코인의 실시간 캔들이 나옵니다(1분/15분/1시간). 지정가·체결가·손절·익절 선과 진입▲·청산▼ 표시가 들어가고, 보유 중이면 15초마다 갱신합니다. 아래에는 방법별 누적 손익 곡선이 있습니다. 차트 라이브러리는 트레이딩뷰 공개 lightweight-charts를 쓰므로 휴대폰에 인터넷이 필요합니다.
  - 버튼: 정지·재개·전체 청산 (확인 창 있음), **💰 예산 수정**.
  - 예산 수정 순서: 칸에 금액 입력 → 다음 → 바뀌는 내용 확인 → (올릴 때는 화면 비밀번호 다시) → 적용.
  - 적용하면 바로 반영되고, config.yaml에도 저장되며(이전 파일은 `data/config_backup/`), 텔레그램으로 알림이 갑니다.
  - 제한: 최소 금액(H3 180 · H4 350 · H5 180) 미만 불가(0 = 끄기). 실계좌는 세 칸 합계가 바이비트 USDT 잔고를 넘을 수 없습니다.
  - 한도 %·레버리지·모드(실계좌 켜기)를 바꾸는 버튼은 없습니다(설정 파일만).
  - 밖에서 보려면 Tailscale(사설망, 권장) 또는 ngrok(공개 주소, 강한 비밀번호 필수)을 직접 설치해야 합니다. 이 PC에서 ngrok은 찾지 못했습니다.

## 5. live 켜기 (사용자만)
코드·웹·텔레그램 어디에도 live로 바꾸는 기능은 없습니다. 아래 다섯 가지를 **모두** 직접 해야 live 장부가 켜집니다.
1. `.env`에 `BYBIT_LIVE_API_KEY`, `BYBIT_LIVE_API_SECRET`을 넣습니다(출금 권한 없는 키).
2. 같은 폴더에 `LIVE_CONFIRM.txt`를 만들고, 첫 줄에 정확히 `LIVE TRADING CONFIRMED BY OWNER`를 씁니다.
3. `config.yaml`의 live 장부 블록 앞 `#`을 지웁니다(예산 H3 300, 관문 block).
4. 바이비트 계정 마진 모드가 격리인지 확인합니다.
5. 봇을 재시작합니다. 웹 화면에 `[live] 작동 중`이 보이면 켜진 것입니다.

끄려면 config의 live 블록을 다시 주석 처리하거나 `LIVE_CONFIRM.txt`를 지우고 재시작합니다. 그 전에 휴대폰에서 /청산으로 정리하세요.

## 6. 한도 (config.yaml에서만)
- **예산 칸(방법마다)**: 최소 H3 180 · H4 350 · H5 180 USDT입니다. 이보다 작으면 그 방법은 꺼지고, 화면에 이유가 표시됩니다. 이 위로는 마음대로 적으면 됩니다(0 = 안 씀). 봇은 그 금액 안에서만 움직입니다(증거금 합 ≤ 예산, 격리 마진).
- 포지션당 위험은 예산의 0.25%(상한 2%)입니다. 최소 주문 때문에 0.5%를 넘으면 그 신호는 건너뜁니다. 최소 금액에서는 거래당 위험이 약 0.5%가 됩니다.
- 일일 손실 6%: **투자 방법(H3·H4·H5)마다 따로** 계산합니다. 그 방법의 예산 대비 그날(KST) 손실이 6%면 그 방법만 그날 신규 진입을 멈춥니다. 다른 방법은 계속 돌고, 다음 날 자동으로 다시 열립니다.
- 누적 손실 20%: 이것도 방법마다 따로입니다. 그 방법만 정지하며, 풀려면 `cumulative_reset_id`를 1 올리고 재시작합니다(수동 재개만 가능).
- 레버리지: 청산가가 손절가보다 5%p 이상 멀도록 자동으로 정합니다(보통 4배, 상한 5배).
- API 실패나 주문 거부(재시도 후): 알림을 보내고 그 장부 진입을 멈춥니다. 확인한 뒤 /재개합니다.

## 7. 기록과 분석
- `data/bot.db` (SQLite):
  - `signals`: 사이트 사건 + 사이트 결과
  - `decisions`: 모든 신호의 진입/건너뜀 + 이유 + 레짐
  - `legs`: 주문 단위. 신호가·지정가·체결가·수수료·펀딩·손익·보유시간·레짐·사이트 결과
  - `execs`: 거래소 체결 원본
  - `events`: 오류·경고
- 웹 화면의 CSV 버튼으로 `legs`를 내려받을 수 있습니다.

## 9. 알려진 한계
- paper 체결은 1분봉 기준 가정입니다. 지정가는 저가가 지정가보다 낮아야 체결되고, 손절은 시가 갭을 반영합니다. 실제 체결과 다를 수 있고, 그 차이를 재려고 demo·live를 돌립니다.
- 체결 뒤 손절 이동(H4 b, H5)은 거래소 조건 주문 가격을 수정해서 합니다. 수정이 안 되면 새 손절을 걸고 옛것을 취소합니다. 데모에서 실제 동작을 확인해야 합니다.
- 진입가가 지정가보다 낮게 체결되면, 손절은 지정가 기준 −15%로 남습니다(체결가 기준보다 조금 위).
- 사이트 결과는 수수료 0.11%를 뺀 숫자입니다. 실전 숫자는 실제 수수료·펀딩·슬리피지가 모두 들어갑니다. 이 차이가 측정 대상입니다.
- 레짐 계산은 바이비트 BTCUSDT 무기한 1시간봉을 씁니다. 연구는 바이낸스 현물을 썼고, 값은 거의 같지만 완전히 같지는 않습니다.
